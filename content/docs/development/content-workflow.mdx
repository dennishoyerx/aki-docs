## Add a page

1. Create an `.mdx` file in the matching folder under `content/docs`.
2. Add frontmatter with a concise `title` and `description`.
3. Add the filename to that folder's `meta.json` `pages` list.
4. Use relative conceptual links or stable `/docs/...` URLs for related pages.

The six sidebar groups are intentionally fixed:

- Introduction
- Architecture
- Runtime
- Extending
- Reference
- Development

Keep new pages inside one of those groups so the navigation remains predictable.

## Verify the public surface

Run the checks below after editing content or routes:

```bash
bun run typecheck
bun run build
PORT=3000 bun run start
curl -i http://localhost:3000/llms.txt
curl -i http://localhost:3000/llms-full.txt
curl -i http://localhost:3000/docs/introduction.md
curl -i 'http://localhost:3000/api/search?query=Rev'
```

The local search route and MCP `search` tool must return a real matching page. The `list_pages` and `get_page` tools must use the same source and processed Markdown representation as the HTTP routes.

## Content boundaries

Write concise English suitable for an open-source repository. Describe public behavior and stable boundaries. Do not paste audits, task lists, credentials, private runtime state, or source-tree paths that are not part of the public contract.
