Aki is a capability runtime. It turns a request into a deliberate action, resolves that action to a versioned capability, and invokes the implementation behind it.

The core chain is small:

```text
request → Agent decides → Rev resolves → executor runs → result
                                      ↘ Ren presents kind=ui
                         Store supplies context-bound data
```

The documentation is organized around that chain. Start with the [architecture map](/docs/architecture), then use the runtime and extending guides to connect the model to an implementation. The [reference section](/docs/reference) keeps route and capability details close at hand.

## The short version

- **Agent** interprets the conversation and chooses an available action.
- **Rev** owns capability identity, versions, active selection, resolution, and invocation.
- **Ren** presents Rev functions whose `kind` is `ui`; it is not a second registry.
- **Store** provides context-bound data access with independent namespace policy.
- **Executors** include native handlers, plugins or processes, graphs, HTTP calls, LLMs, and MCP integrations.

A plugin can change how a capability runs without changing what the capability is. A browser `/api/...` prefix can be a proxy convention without becoming a kernel route. Those boundaries are the most useful things to keep in mind while reading the rest of the site.
