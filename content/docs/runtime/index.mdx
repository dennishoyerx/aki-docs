The runtime is the active side of the architecture. It receives requests, gives the Agent enough context to decide, resolves the selected capability through Rev, and returns a result through the same execution chain.

## Invocation path

A capability invocation is a sequence of contracts:

1. The caller supplies a capability name, arguments, and inherited context.
2. Rev identifies the capability and selected version.
3. Rev checks declared Store requirements and preconditions.
4. The executor performs the implementation-specific work.
5. The result returns through the same boundary to the Agent or client.

The executor can be native code, a plugin or process, a graph, an HTTP endpoint, an LLM call, or an MCP integration. The public capability identity remains the Rev identity.
